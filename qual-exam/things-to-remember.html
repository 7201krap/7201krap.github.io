Things to remember

Instance method vs. static method

  • A static method is a method declared with the static keyword. It can be called without creating an object.
  • A static method belongs to the class, while an instance method belongs to an instance of the class.
  • An instance method can access instance methods and variables.
  • An instance method can access static methods and variables.
  • A static method can access static methods and variables.
  • A static method cannot access instance methods and variables.

Call stack

  • A dynamic data structure maintained in RAM by the OS.
  • Its purpose is to control the way procedures and functions call each other and pass parameters to each other.
  • Local variables on the call stack are part of the root set in garbage collection.

Procedure call

  • Things that always happen on a procedure call:
    • The program counter is updated.
    • The stack pointer is updated (the return address is saved on the stack).
  • Stack pointer register: to push data onto or pop data from the stack, the machine must remember how far the stack currently extends. When the called function returns, the stack pointer is moved back by one stack frame.

Stack frame

  • A stack frame is a frame of data that gets pushed onto the stack. In the case of the call stack, a stack frame represents a function call and its argument data.
  • The function's return address is pushed first, then the arguments and space for local variables. Together they make the frame.
  • The stack region of memory holds the local variables and parameters associated with function calls.
  • The stack region is allocated when a function is called and released when the call completes.
  • When a function is called, its parameters, its local variables, and the return address are stored on the stack.

Functional completeness

  • {NOT, AND}
  • {NOT, OR}
  • {XOR, AND}
  • {XOR, OR}

Sequential vs. combinational circuits

  • Sequential circuit: e.g. a counter (flip-flops with gates); stores memory or state.
  • Combinational circuit: arithmetic and logic operations, or direct control.
  • Decoder: takes an n-bit address and activates one of 2n individual output lines. It turns one input into many outputs, i.e. it sends data to the appropriate output line.
  • Multiplexer: selects one of 2n input lines and connects it to the output line. It outputs one of several inputs.

DMA (direct memory access)

  • DMA lets an I/O device send data to or receive data from main memory directly, bypassing the CPU, to speed up memory operations.

Distributed systems

  • A collection of independent computers that appears to its users as a single system.
  • Why do we need distributed systems? (1) Limited resources, (2) tolerance to failures, (3) convenient access to resources.

Symmetric difference

Static (lexical) scoping vs. dynamic scoping

  • Static (lexical) scoping: a variable or function is resolved using the context of where it is defined.
  • Dynamic scoping: a variable or function is resolved using the context of where it is called. Follow the chain of calls and use the variable defined there; if something was defined earlier, it is simply overwritten.

Direct vs. indirect representation

  • Direct representation (stack storage): accessing a component is fast.
  • Indirect representation (heap storage): compilation is fast.
  • When the storage size of some private component of a variable changes, indirect representation minimizes the number of source modules that must be recompiled.

Ripple-carry adder

  • Computation time for k bits: Tc × (k − 1) + Ts
    • Tc: carry output delay
    • Ts: sum output delay

Semi-space copying collection

  • Assume a "from" space and a "to" space.
  • Discard everything dead in the "from" space and copy only the live objects to the "to" space.

Church–Turing thesis

Also called Church's thesis, Church's conjecture, or Turing's thesis.

  • The thesis says that every computation that can be carried out by mechanical means can be carried out by some Turing machine.
  • Every effective computation or algorithm can be executed on a Turing machine.
  • The thesis does not have the form of a theorem and cannot be proved.

Master theorem

  • The master theorem is a quick and simple way to compute the time complexity of recurrence relations (divide-and-conquer algorithms).

Raymond's tree-based algorithm

  • Raymond's tree-based algorithm guarantees freedom from deadlock, but starvation may occur.

Four principles of object-oriented programming

  • Encapsulation: bundling data and behavior into a class.
  • Inheritance.
  • Abstraction: defining common attributes and behavior reduces code duplication, sets up relationships between classes effectively, and makes maintenance easier.
  • Polymorphism: e.g. overloading.

Quantifiers

  • (∀x P(x)) ∨ (∀x Q(x)) → ∀x (P(x) ∨ Q(x)). The reverse direction does not hold: you can combine, but you cannot split.
  • (∃x P(x)) ∨ (∃x Q(x)) → ∃x (P(x) ∨ Q(x)). Again the reverse direction does not hold.

1's complement vs. 2's complement

  • 1's complement
    • Method: invert every bit.
    • For example, the 1's complement of 0011 is 1100.
  • 2's complement
    • Method: invert every bit, then add 1 at the LSB.
    • The most significant bit (MSB) is used as the sign bit: 0 means positive, 1 means negative.
    • For example, the 2's complement of 0010 (decimal 2) is found as follows: 0010 → invert → 1101 → add 1 at the LSB → 1110 (decimal −2).
    • 0010 + 1110 = 10000; the leading 1 is discarded because there were only 4 bits to begin with.

Logic

  • Tautology: always true.
  • Contradiction: always false.
  • Contingency: sometimes true, sometimes false. A proposition that is neither true under every valuation (a tautology) nor false under every valuation (a contradiction).
  • Satisfiability: at least one valuation makes it true.

Static allocation vs. stack allocation

  • Static allocation cannot create data structures dynamically (no recursive procedures).
  • Stack allocation creates data structures and objects dynamically (recursive procedures are possible).

Garbage collection

  • Reference counting
    • A smart pointer maintains a reference count internally and frees the object's memory when the count reaches 0.
    • Objects whose reference count is 0 can be considered no longer in use and become candidates for garbage collection.
    • Objects in a cycle that is unreachable from the GC roots are also candidates for collection.
    • Downsides: tracking the reference counts adds overhead, and cyclic references can cause memory leaks.
  • Mark and sweep
    • Starting from the GC roots, identify the reachable objects; clean up the unreachable ones so that their memory can be reused.
    • Mark: starting from the GC roots, identify and record every reachable object.
    • Sweep: free the memory of the objects not identified in the mark phase, i.e. the unreachable ones, so it can be reused.
    • It suffers from memory fragmentation.
  • Stop the world
    • When garbage collection runs, the application threads must pause, because live objects can only be identified accurately while the application threads are stopped.
    • This pausing of application threads is called "stop the world".
