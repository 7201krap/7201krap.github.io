Computer architecture

Cache coherence protocols

  • Definition
    • Cache coherence concerns the situation where multiple processor cores share the same memory hierarchy but have their own L1 data and instruction caches. Incorrect execution can occur if two or more copies of a cache block exist in different processors' caches and one of them is modified (ScienceDirect).
    • In short, it is the problem of keeping the data in the caches consistent (ques10).
  • Solution 1: snooping-based protocol
    • Broadcast messages are used and the caches are connected through a bus.
    • Each cache constantly monitors the address bus for accesses to memory it holds. When a write occurs in another cache, the cache controller invalidates its own copies of that block.
  • Solution 2: directory-based protocol
    • A directory records which nodes hold copies of each cache block, so requests are sent only to those nodes. No broadcast is needed, so relatively little bandwidth is required.

Copy-on-write vs. read-write

  • Copy-on-write: a new copy of the data is created only when the original data is actually modified. Until then, the process continues to read from the original.
  • Read-write has no such mechanism: reads and writes are performed directly, as the name says.
  • The difference: copy-on-write is used when the contents will be changed; if the data is simply being copied, read-write is used.

Pipelining (5-stage pipeline)

  • An instruction is executed in the order IF, ID, EX, MEM, WB.
  • IF, instruction fetch: fetch the instruction from memory.
  • ID, instruction decode: read and decode the instruction; read the registers.
  • EX, execute: perform the operation.
  • MEM, memory access: access memory.
  • WB, write back: write the result to a register.

Single-cycle vs. multi-cycle implementation

  • Single-cycle implementation: all five stages of one instruction are executed within one clock cycle.
  • Multi-cycle implementation: operations can be pipelined. The cycle needs to be long enough for the slowest functional unit (one of IF, ID, EX, MEM, WB) to settle. For example, if memory takes M ns, the register file R ns, and the ALU A ns, then the cycle cannot be shorter than max(M, R, A).

Cycles per instruction (CPI)

  • The average number of clock cycles per instruction executed.
  • CPI = Σ (frequency of the instruction) × (number of cycles of the instruction).

Subroutine

  • A sequence of program instructions that performs a specific task.

Stack-organized computer

  • A stack-organized computer is characterized by zero-address instructions.

Write-through vs. write-back

  • Write-through: updates are written to both the cache and main memory.
  • Write-back: updates are written only to the cache, not to main memory. Data stays in the cache temporarily, and is written to main or secondary memory in block units only when the block is evicted from the cache.

Memory-mapped I/O

  • I/O ports are placed at addresses on the bus and are accessed just like other memory locations.

  • Variable-length ISAs allow a smaller code size than fixed-length ISAs. True.
  • Fixed-length ISAs simplify instruction fetch and decode compared with variable-length ISAs. True.
  • Variable-length ISAs (CISC) require more registers than fixed-length ISAs (RISC). False. RISC requires more registers than CISC.

Operand forwarding

  • An optimization in pipelined CPUs that limits the performance loss due to pipeline stalls.
  • A data hazard can lead to a pipeline stall when the current operation has to wait for the result of an earlier operation that has not yet finished.
  • A stall is a cycle in the pipeline without new input; think of it as idle waiting time.
  • Operand forwarding is used to minimize data-dependency stalls in the pipeline.
  • With operand forwarding, the interface registers between stages hold intermediate outputs, so a dependent instruction can read the value directly from the interface register.
  • Forwarding reduces the number of stall cycles in the pipeline.
