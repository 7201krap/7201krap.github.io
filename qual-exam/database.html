Transaction log

Also known as the database log or binary log.

  • It stores a record of all data changes made to the database.
  • It guarantees the ACID properties of the database.
  • ACID is the set of properties that guarantee a database transaction is executed safely:
    • Atomicity: the operations in a transaction are never partially executed and then interrupted; either all of them happen or none of them do.
    • Consistency: data can only be modified in ways allowed by predefined rules.
    • Isolation: other transactions cannot interfere with a transaction while it runs.
    • Durability: a successfully committed transaction is permanently reflected in the database.

NoSQL

  • Not a relational database; relationships between tables are not defined.
  • Data is represented as (key, value) pairs and only input/output by key is supported. No JOIN is needed. Handles very large volumes of data. No schema. Downside: data updates are slow.

Normalization

  • Normalization is the process of deciding the structure of the data during relational database design so as to minimize data redundancy.
  • Typically, large and poorly organized tables are broken into smaller, well-organized tables.

Clustered vs. non-clustered index

  • Clustered index
    • Defines the order in which data is physically stored in the table.
    • Example: a dictionary.
  • Non-clustered index
    • Stored in one place while the table data is stored in another.
    • Example: the index at the back of a book.
  • Some facts:
    • A table can have only one clustered index.
    • A table can have multiple non-clustered indexes.
    • A clustered index is faster than a non-clustered index.

Normal forms

  • 1NF: a relation is in first normal form if the domain of every attribute consists of atomic values only.
  • 2NF: a relation is in second normal form if it is in 1NF and has no partial dependencies, i.e. no non-key attribute depends on only part of the primary key. A partial dependency is a dependency on only one of the keys of a composite primary key; without a composite primary key there is no partial dependency. In practice, columns unrelated to the core subject of the table are moved out.
  • 3NF: a relation is in third normal form if every non-key attribute is functionally dependent on the primary key only. Columns that depend on an ordinary (non-key) column are moved to a separate table.
